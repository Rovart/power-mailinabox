Filtering

Incoming mail goes through a few checks before it is accepted. The first time a server sends mail from a new sender, it is asked to try again a few minutes later (greylisting), which most spam senders never do. Here you can let the mail servers you trust skip that wait, and refuse mail from senders you never want to hear from.

Allowed servers

Mail from these servers is accepted without greylisting. The other checks (Spamhaus, SPF, DKIM, DMARC and the spam filter) still apply.

A host name, which also covers its subdomains (x.com covers mail.x.com), or an IP address or network. Sender addresses can be forged, so servers are matched by their verified reverse DNS name instead.

    Blocked senders

    Mail from these senders or servers is refused before it is accepted: it doesn’t reach any mailbox, and the sending server gets an error.

    An email address, a domain (which also covers its subdomains) or the IP address or network of a server. Addresses and domains are matched against the sender of the message envelope (its return path).

      Login protection

      Password guessing against the box’s logins comes from thousands of addresses that each try a few times. Besides fail2ban, which bans addresses after repeated failed logins, the box can block the addresses already known for these attacks and tell you when an account logs in from somewhere new.

      IP blocklists

      The blocklists aren’t available because the firewall was disabled when the box was set up (DISABLE_FIREWALL).

      Connections from the addresses on these lists to the login ports () are dropped. Port 25 is never blocked, so mail from other servers still arrives. The lists are downloaded every 6 hours and merged without duplicates. A list that fails or has no valid entries adds nothing. The box’s own addresses, fail2ban’s ignored addresses and the networks your users logged in from in the last 30 days are never blocked.

        A text file with one IP address, network (192.0.2.0/24) or range per line; comments after # are ignored. JSON lines with a cidr key (like Spamhaus DROP) work too.

        Logins from new places

        The administrator gets an email when an account logs in (to send mail, or to IMAP or POP) from a network it never used before: a stolen password shows up there. Networks are /24 for IPv4 and /64 for IPv6. Logins from the webmail and the other apps on this box aren’t counted.
