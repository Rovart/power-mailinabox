Filtering

Incoming mail goes through a few checks before it is accepted. The first time a server sends mail from a new sender, it is asked to try again a few minutes later (greylisting), which most spam senders never do. Here you can let the mail servers you trust skip that wait, and refuse mail from senders you never want to hear from.

      Login protection

      Password guessing against the box’s logins comes from thousands of addresses that each try a few times. Besides fail2ban, which bans addresses after repeated failed logins, the box can block the addresses already known for these attacks and tell you when an account logs in from somewhere new.

      IP blocklists

      The blocklists aren’t available because the firewall was disabled when the box was set up (DISABLE_FIREWALL).

      Each list blocks either the login ports (, keeping port 25 open so mail from other servers always arrives, and the web) or every port except DNS (53), for lists of networks that never have a reason to connect. The lists are downloaded every 6 hours and merged without duplicates. A list that fails or has no valid entries adds nothing. The box’s own addresses, fail2ban’s ignored addresses and the networks your users logged in from in the last 30 days are never blocked. Sites behind a CDN or reverse proxy only see its addresses, so these lists don’t protect them.

        A text file with one IP address, network (192.0.2.0/24) or range per line; comments after # are ignored. JSON lines with a cidr key (like Spamhaus DROP) work too.

          Countries

          The country filter isn’t available because the firewall was disabled when the box was set up (DISABLE_FIREWALL).

          Allow only the countries your users connect from, or block the ones you never expect logins from. Port 25 is never filtered, so mail from other servers always arrives, and neither are port 80 (Let’s Encrypt) and DNS. Never blocked: addresses that aren’t on the internet (your local network, Tailscale and other VPNs: 100.64.0.0/10 and private IPv6), and the same addresses the blocklists never block, including the networks your users logged in from in the last 30 days. So a user who is abroad now keeps working, but one who travels to a country that isn’t allowed is blocked there: add it before the trip. A country is where each block of addresses is registered, from the regional internet registries’ data, downloaded once a day. If there is no data for a chosen country, nothing is blocked by country.

          HTTPS is also the webmail, Nextcloud, Exchange ActiveSync, this control panel, the websites this box serves and other mail servers’ MTA-STS checks. Port 80 is never filtered. You can’t choose a setting that blocks your own connection.

            Logins from new places

            The administrator gets an email when an account logs in (to send mail, or to IMAP or POP) through an internet provider’s block of addresses it never used before (another provider, or another country): a stolen password shows up there. Blocks are /16 for IPv4 and /32 for IPv6, so a phone that gets a new address every time it connects doesn’t send an email each time. Logins from the webmail and the other apps on this box aren’t counted. Locations come from RIPEstat (only the address is sent) and are approximate: for mobile connections they show where the operator’s network meets the internet, not where the phone is.

            How to use it
            1. In your CDN or WAF, create an IP list (it may be called an IP set, an access control list or a network list).
            2. Upload the file to it, or paste its contents. Most lists add to their entries rather than replace them: to start over, empty the list first.
            3. Add a rule that blocks the requests whose client address is on that list, and apply it to each site behind the CDN.
